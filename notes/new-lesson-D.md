# Zabon Lesson Generation Instructions

## Metadata (Read from context)

- `file`: output file path
- `level`: 1–9 (determines linguistic complexity)
- `proficiency`: beginner / intermediate / advanced (determines length)
- `translations`: list of all 7 languages (en, th, fa, ar, es, zh, ja)
- `targets`: languages being taught (pedagogical focus applies to these)
- `focus`: grammar topic (must be naturally integrated)

## Length & Complexity

- **Beginner** (levels 1–3): 20–25 sentences total.
- **Intermediate** (levels 4–6): 30–35 sentences.
- **Advanced** (levels 7–9): 40–50 sentences.
- Sentences are distributed across at least 5 conversational scenarios.

## Structure (Strict Order)

The JSON `"items"` array must follow this exact sequence:

1. **Scenario Headers + Sentences** (all scenarios, one after another)
   - Each scenario starts with a header `"header_scenario_N"` (N starting at 1).
   - Then the sentences (`"sentence_*"`) that form a cohesive back‑and‑forth dialogue for that scenario.
   - Minimum 5 sentences per scenario (to ensure realistic exchange).

2. **Scenario Word Lists** (after all sentences, in the same scenario order)
   - For each scenario, place a word header `"header_scenario_N_words"`.
   - Then the word items (`"word_*"`) extracted from that scenario.
   - **No global `header_words`** – only scenario‑specific word headers.

Example order (abbreviated):

header*scenario_1
sentence_1
sentence_2
...
sentence_5
header_scenario_2
sentence_6
...
...
header_scenario_1_words
word_1
word_2
...
header_scenario_2_words
word*...
...

## Vocabulary Extraction Rules

- **Extract** content words (nouns, main verbs, adjectives, adverbs) and any grammar particles that are the lesson’s `focus`.
- **Do NOT extract** stop‑words unless they are the specific focus:
  - Personal pronouns (I, you, he, she, it, we, they)
  - Basic prepositions (of, to, for, with, at, from, etc.)
  - Articles (a, an, the)
  - Common conjunctions (and, but, or, so)
  - Auxiliary verbs (be, have, do) – unless the focus is on them.
- Use the **exact form** as it appears in the spoken sentence (e.g., "I'm", "don't", "went" – not "I am", "do not", "go").
- **Duplicate words across scenarios are NOT allowed.** If a word appears in multiple scenarios, extract it **only in the first scenario** where it appears. Do not create a new `word_*` for later scenarios.
- Ensure every extracted word’s text is a **substring** of at least one sentence in the **same scenario**.

## Sentence Generation

- Each scenario must be a **cohesive dialogue**: speakers respond directly to the previous line.
- Aim for balanced turn‑taking (no long monologues).
- **No `speaker` field** – it is not used in the app.

## Tokens (All Languages)

- **All 7 languages** must have a `"tokens"` array in every sentence.
- For **whitespace languages** (`en`, `fa`, `ar`, `es`):
  - Tokens must be the exact words when joined with a single space.
  - Punctuation (., ? ! , etc.) must remain attached to the preceding word.
- For **segmenter languages** (`th`, `zh`, `ja`):
  - You **MUST** provide token arrays generated by the appropriate segmenter (`wordcut` for Thai, `segmentit` for Chinese, `tiny-segmenter` for Japanese).
  - These tokens are critical for the app; do not omit them.
  - The validation script will error if they are missing.

## Error Handling (Partial Regeneration)

If validation fails on specific items, output **only** the corrected JSON blocks (sentences or words) as a JSON array, clearly labelled, so they can be replaced manually.

## Output Format

- Output **only** the JSON object (no markdown, no explanations).
- First character `{`, last character `}`.
